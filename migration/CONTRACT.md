# Implementation contract

This small contract documents interfaces, not a parallel authority. DECISIONS.md and MIGRATION_PLAN.md govern behavior.

- One private package. Parent owns package.json, lockfile, src/contracts.ts, src/cli.ts, generated dist and integration.
- Canonical skills keep current `metadata.mpx` schemaVersion/skillPacks/defaultExposure; missing exposure is explicit-only for exclusively personal packs, normal otherwise. Skill directory and frontmatter name use bare names; projections use mp-.
- Canonical agents use bare filenames/names and metadata.mpx {schemaVersion:1,modelClass,thinking,capabilities}; projections use mpx-, including explorer (never alias it to Explore). Preserve semantic model classes in canonical bodies.
- Runtime profile is content/runtime-profiles.json: {schemaVersion:1,models:{pi,claude},tools:{pi,claude}}. No old alias/manifest/gateway mappings.
- Compiler API in src/compiler.ts: projectContent(root:string): Promise<Projection[]>; build(root:string): Promise<BuildResult>; checkOutput(root:string): Promise<string[]> (drift paths). Pure projection then scoped build. Output only dist/packs, dist/pi, dist/claude. Never overwrite links or delete outside these generated roots.
- Compiler placeholders are double-braced uppercase identifiers; ordinary Vue/React/Handlebars example syntax is preserved verbatim. Declared body placeholders only: {{MPX_SKILL_COMMAND}} => /skill:mp- or /mp-; {{MPX_AGENT_PREFIX}} => mpx-; {{MPX_SHARED_INSTRUCTIONS}} => relative path from output file to dist/<harness>/instructions/shared; {{MPX_AGENT_REFERENCES}} => relative path to dist/<harness>/agents/references. {{MPX_HARNESS}} => pi or claude. Other uppercase named tokens and unresolved/malformed reserved MPX tokens fail, rather than guessing. Support files otherwise copied byte-for-byte; only text with declared placeholders transformed. Preserve literal framework/template examples rather than silently erasing them.
- Content output: instructions/{shared,pi} -> dist/pi/instructions/{shared,pi}, likewise Claude; agents/references support retained; rules, hooks, output-styles mirrored under each harness. Do not expose unadapted content to make a build pass.
- Config API src/config.ts: parseRepositoryConfig(value:unknown): RepositoryConfig (throw direct diagnostic); readUserConfig(file:string,env?:NodeJS.ProcessEnv): Promise<UserConfig>; resolveProject(cwd:string): Promise<ProjectSelection>; selectPacks(root:string,harness:Harness,account:Account,project:ProjectSelection,user?:UserConfig): Promise<PackSelection>.
- User config explicit account roots required; ${MPX_*} expansion only approved root/executable allowlist, unset is error for required config path. No guessed roots. Default config file location resolved by CLI from APPDATA/mpx2/config.json. No installed config edits at this stage.
- Repository shape is documented by src/contracts.ts. Invalid/missing config means unregistered; invalid config warns and falls back. Linked worktrees use main checkout. Packs may be any safe lowercase bare pack name available under dist/packs, explicit [] preserved. Personal defaults development+personal, work development. Missing fallback path makes MPX pack paths empty (native only), warning. Explicit invalid/unavailable selection warns and falls back to defaults.
- Wrapper args are arrays, never shell-joined. Preserve caller arguments after injected defaults; do not inject model/effort defaults. Pi repeated --skill; Claude repeated --add-dir. No --no-skills. No per-session artifacts, shared link changes, credential routing or extra environment protocols.
- Partial installer API src/install.ts: planAgentLinks(root, config) -> links/errors/scopes; inspectAgentLinks(plan), syncAgentLinks(plan) -> per-entry results/errors. Individual generated specialist links only; existing account roots required, linked ancestors/conflicts preserved, stale entries reported without removal. CLI exposes only explicit --agents-only scope, not a successful full installation.
- Orca mirroring API src/orca.ts: mirrorOrcaHooks(config, {preview?}) defaults to preview; mergeClaudeHookSettings is pure. Only three fixed marked Pi files and matching nested Claude hooks are mirrored personal→work; preserve unrelated settings/statusLine and report absent source, unsafe paths, or target-only metadata conflicts. No source regeneration, whole-account copy or live action occurs implicitly. CLI permits writes only through explicit --orca-hooks-only scope without --preview.
- PolicyResult in src/safeguards/contracts.ts is {decision:allow|warn|block,diagnostics:string[]}. Staged scanning is one streamed bounded Git diff; executable lookup starts from the trusted helper directory and selects the repository via -C, not an untrusted repository cwd. Private-key accumulation does not cross unscanned context/hunks. Diagnostics never reveal matched credentials. The authoritative total budget is below five seconds, not four; default collection timeout is four seconds. Package policy inspects simple statically understood Git Bash invocations, warns rather than guesses unsupported cwd/grammar, and uses no mpxconfig authority or persistent cache. Both CLI checks inspect only; native hook transports remain separate.
- Native-session API src/resume.ts: readPiSession, listNativeSessions, planResume. Read-only Pi v3 metadata/active-branch recovery, bounded payload projection and fatal UTF-8 decoding; no SessionManager migration or transcript rewriting in production inspection. Unknown fields need labeled overrides. Listing/preview are not an operational resume gate; actual model availability, Claude handling and launch verification remain incomplete.
- Pi context helpers use native custom context messages and current active compaction-aware snapshots, not a new session store. Native compact() remains the compactor; manual instructions have priority, hook failures visibly fall back. Only seven approved machine roots and concise style enter model-bound context. Live registration is not performed by tests.
- All tests use node:test via tsx, real disposable temp fixtures where filesystem/Git behavior matters. Narrow red/green evidence required. Native SDK fixture sessions may create/open their own disposable transcripts; production readers may not use rewriting native open APIs. Real provider calls, live accounts and interactive behavior remain separate acceptance gates.
